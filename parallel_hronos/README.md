# parallel_hronos

Параллельный проект для хронометража по подразделениям. Он не меняет основной
пайплайн в корне репозитория.

## Что делает

1. Python читает входные `*.xlsx` и `*.xlsb` из папки, выбирает последние версии
   файлов по суффиксу `__N`, собирает листы `Реестр` в один `Сводный_Реестр`.
2. Python пишет контроль объемов по каждому подразделению:
   `Объем_источники`, `Объем_реестр`, `Отклонение`, `Статус`.
3. C# открывает книгу, превращает `Сводный_Реестр` в умную таблицу `Таблица1`.
4. C# берет шаблон с настоящей Excel PivotTable на листе `Сводная_пески`,
   подменяет реестр и закрепляет источник сводной на `Таблица1` с листа
   `Сводный_Реестр`.
5. C# добавляет `Контроль_сводной` с теми же суммами обычной таблицей для быстрой
   сверки по подразделениям.

## Быстрый запуск

Из папки `parallel_hronos`:

```bash
python3 -m hronos.cli run \
  --output output
```

Эту команду нужно запускать прямо перед отправкой письма: она каждый раз сначала
скачивает новые вложения из `Hronos_torfa`, затем пересобирает реестр, проверку
объемов и лист `Сводная_пески`.

Если дату не указать, берется вчерашняя дата локальной системы. Для отчета это
фильтр сводной `Дата выдачи наряд-задания = выбранная дата`.

Отдельно проверяется свежесть обязательных подразделений `Дражный`, `Обман`,
`Сайлык`, `Талынья`, `Эрел` по колонке `Дата. Факт`. Контрольная дата по
умолчанию — сегодня. Если по какому-то подразделению нет свежего файла, сборка
останавливается до C# и не формирует финальный файл для отправки. Диагностика
пишется на лист `Комплектность_исходников`.

Для диагностики без скачивания и без остановки можно собрать черновик:

```bash
python3 -m hronos.cli run \
  --no-fetch \
  --allow-stale \
  --output output
```

По умолчанию фильтр сводной и контрольная сверка строятся по
`Транспортировка песков` и `Подача песков`. Исходный `Сводный_Реестр` при этом
не фильтруется: ограничения задаются только в PivotTable. Если нужен другой
набор для листов проверки, укажите `--peredel` один или несколько раз:

```bash
python3 -m hronos.cli run \
  --input ../input/mail_attachments \
  --output output \
  --report-date 2026-07-02 \
  --peredel "Транспортировка песков" \
  --peredel "Подача песков"
```

Только Python-консолидация без C#:

```bash
python3 -m hronos.cli consolidate --input ../input/mail_attachments --output output
```

Только C#-постобработка уже собранной книги:

```bash
dotnet run --project tools/pivot/HronosPivotBuilder.csproj --configuration Release -- \
  output/имя_книги.xlsx \
  --out output/имя_книги_final.xlsx \
  --date 2026-07-02 \
  --peredel "Транспортировка песков" \
  --peredel "Подача песков"
```

## Зависимости

Python:

```bash
python3 -m pip install -r requirements.txt
```

C# использует локальный `EPPlus.dll` из основного проекта:
`../tools/pivot/bin/Release/net9.0/EPPlus.dll`.

## Итоговые листы

- `Сводная_пески` — настоящая Excel PivotTable `Дата → Время x Подразделение`.
- `Сводный_Реестр` — полный реестр, умная таблица `Таблица1`.
- `Проверка_объемов` — сверка объемов по подразделениям.
- `Контроль_сводной` — проверочная матрица `Дата/Время x Подразделение`.
- `Файлы` — какие источники были взяты и сколько строк прочитано.
- `Ожидаемая_сводная` — ожидаемые итоги для фильтров сводной по подразделениям.

Исходные файлы не перезаписываются.
