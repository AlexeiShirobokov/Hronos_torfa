## Цель

Перенастроить пайплайн хронометража транспортировки торфов и **перенести его с Mac
(launchd) на сервер `geol-deploy` (37.140.195.93, REG.RU CloudVPS)** — тот же
прод-сервер, что у Geol:

1. Формировать отчёт **ежечасно в окне 6:00–22:00 по Москве** (17 прогонов/день).
2. **Сменить формат доставки: HTML-письмо + Excel** (вместо PDF). PDF убираем
   совсем — его графики перегружены и нечитаемы в рассылке.
3. **Пояснительная записка** — связный текст по итогам дня прозой, генерируется
   моделью через SSH-мост к Claude Code (как в Geol), с детерминированным запасным
   вариантом «по правилам». Встраивается в тело HTML-письма.
4. **Алерты по email** — о сбоях пайплайна и об аномалиях KPI, с анти-спамом.
5. Слать **только на `alexeimvc@gmail.com`** (остальных получателей закомментировать).
6. **Развернуть весь пайплайн на сервере**: Python-venv + cron. **Без Telegram-бота**
   и без systemd-сервиса. Письмо уходит автоматически (гейт подтверждения не нужен —
   получатель сам пользователь).

Принцип: новые части не ломают сборку данных. Мост — best-effort (сбой моста не
прерывает отчёт). Доставка — только email.

## Фазы внедрения

Поскольку исходящий SMTP с сервера заблокирован REG.RU (см. ниже), внедрение делим
на две фазы:

- **Фаза 1 — сейчас, на Mac.** Реализуем новый дизайн (HTML-письмо + Excel + записка
  + алерты + один получатель) и запускаем на Mac через существующий launchd
  (расписание 6–22). **Рассылку делаем с Mac** — отсюда SMTP не блокируется
  (проверено: `send_email.py --check` → `[OK] SMTP-логин принят`).
- **Фаза 2 — позже, перенос на сервер geol-deploy.** Когда REG.RU откроет исходящий
  SMTP (по тикету), переносим пайплайн на сервер (venv + cron) и снимаем launchd на
  Mac. До этого момента Часть 6 (развёртывание) — отложена.

Весь код пишется одинаково для обеих фаз; различается только место запуска
(launchd на Mac ↔ cron на сервере) и факт работающего SMTP.

## Внешняя зависимость: исходящий SMTP (диагностировано)

Отправка писем (`SMTP_SSL` на `smtp.yandex.ru:465`) **с сервера не работает**.
Диагностика показала: **блокировка на стороне хостинга (REG.RU), не на сервере**:

- Локальный фаервол чист: `iptables -P OUTPUT ACCEPT`, в `ufw` нет правил против
  465/587/25.
- Проба портов: исходящие 25/465/587 ко всем (yandex/gmail/mail.ru) — **таймаут 6с**
  (молчаливый дроп); контрольный `example.com:443` — открыт за 0.1с. → провайдерский
  фильтр исходящего SMTP ко всем адресам.

**Решение (выбор пользователя):** тикет в поддержку REG.RU на снятие блокировки
исходящего SMTP (465/587). Релей через EU-сервер **не используем**. Код отправки от
этого не зависит — заработает после открытия порта.

- Текст заявки подготовлен (передан пользователю; способ подачи — тикет в ЛК REG.RU).
- Проверка после открытия на сервере: `.venv/bin/python send_email.py --check` → `[OK]`.
- **Интерим (порт закрыт):** работаем по Фазе 1 — пайплайн и **рассылка идут с Mac**,
  где SMTP доступен (проверено). Доставка отчёта и алертов работает штатно. Перенос
  на сервер (Фаза 2) — после открытия порта; код отправки при этом не меняется.

## Поток выполнения run_daily

`fetch → consolidate (реестр + csv) → analytics (метрики + листы Excel) → explain

Алерты о сбоях шага отправляются email-ом в точке сбоя (до раннего выхода); алерты
об аномалиях — после `explain`. Все алерты проходят анти-спам.

## Часть 2. Аналитика → Excel (листы) + метрики

Текущий `build_pdf.py` считает все агрегаты и рисует PDF. Аналитику выносим в Excel,
PDF убираем.

### 2.1 Модуль `analytics.py` (новый, рефактор из build_pdf)

- `compute(csv_path) -> dict` — возвращает агрегаты как DataFrame'ы и сводные числа:
  итоги (объём, рейсы, м³/рейс, водители, самосвалы, подразделения), `by_unit`,
  `by_date`, `by_hour` (на отчётную дату), `drivers` (с ABC), `truck_mark`,
  `truck_inv`, `idle`. Это перенос существующей логики `build_pdf.main()` без
  отрисовки.
- `dump_metrics(aggr) -> state/last_metrics.json` — компактный JSON для записки и
  алертов (см. 3.x).

### 2.2 Excel: реестр + листы аналитики

`consolidate.py` уже строит книгу с реестром («Сводный_Реестр»). Добавляем шаг
`build_xlsx.py`, который дописывает в эту же книгу листы аналитики (openpyxl):

- `Подразделения` — by_unit (рейсы, объём, доля %, м³/рейс, водители, самосвалы).
- `Дни` — by_date (дата, рейсы, объём, м³/рейс).
- `Водители_ABC` — drivers (рейсы, объём, доля %, накопл %, класс ABC, подразделение).
- `Парк_марки` — truck_mark (марка, самосвалов, кузов, рейсы, объём, м³/рейс, исп. %).
- `Парк_инв` — truck_inv (по инв. №).

Форматирование лёгкое (заголовки жирным, числа с разделителями) — без графиков.

## Часть 3. Пояснительная записка через мост + аномалии

### 3.1 Модуль `llm.py` (новый)

Копия моста из Geol: `available()` + `ask(prompt, timeout=None)` → `ssh … "claude -p"`,
промпт в **stdin**. Env с дефолтами: `EU_CLAUDE_SERVER=185.200.179.31`,
`EU_CLAUDE_USER=root`, `EU_CLAUDE_KEY=~/.ssh/eu_claude`, `EU_CLAUDE_TIMEOUT=300`.
Только стандартная библиотека.

### 3.2 Модуль `explain.py` (новый)

1. Читает `state/last_metrics.json`.
2. Формирует «бриф данных» (плоский текст с цифрами) + инструкцию: деловой стиль,
   3–6 абзацев — итоги дня, динамика к прошлому дню, узкие места, рекомендации;
   **ничего не выдумывать сверх данных**.
3. `llm.available()` → `llm.ask(brief)`; иначе/при ошибке → `_rule_based_note()`
   (шаблон из тех же чисел).
4. Считает аномалии (3.4) → `state/last_alerts.json` (`[{type, text}]`).
5. Сохраняет `output/Пояснительная_записка_<дата>.md` и `state/last_note.txt`,
   возвращает текст записки (для HTML-письма).

### 3.3 Пороги аномалий (константы, переопределяемы через `.env`)

- `MIN_BODY_UTIL = 95` — средняя загрузка кузова, % (ниже → алерт);
- `MAX_IDLE_H = 1.0` — простои, ч/смену (выше → алерт);
- `MAX_VOLUME_DROP = 30` — падение объёма к прошлому дню, % (больше → алерт).

### 3.4 Алерты по email + анти-спам

- Канал — email на админ-адрес (`alexeimvc@gmail.com`). Хелпер `alert(subject, text)`
  в `run_daily.py` шлёт короткое письмо с префиксом `⚠️`.
- **Сбои:** `consolidate`/`build_xlsx`/`analytics` упали; `fetch` без свежих данных /
  дата отчёта не сегодняшняя.
- **Аномалии:** из `state/last_alerts.json` (пороги 3.3).
- **Анти-спам:** `state/alerts_sent.json` — ключи `"<дата>|<тип>"`; каждый уникальный
  алерт отправляется один раз за день (важно при 17 прогонах).

## Часть 4. HTML-письмо (автоотправка)

`send_email.py` переводим с plain-text на **HTML** (`EmailMessage.add_alternative`,
с текстовой версией для совместимости). Состав HTML-тела:

- Заголовок + отчётная дата.
- **Пояснительная записка** прозой (из `explain.py`).
- **KPI** — компактные плитки/строка: объём, рейсы, м³/рейс, водители, самосвалы.
- **Таблица «Подразделения»** — by_unit (5 строк).
- **Таблица «Динамика»** — последние ~7 дней (дата, объём, рейсы, м³/рейс).
- **Аномалии** — выделенный блок, если список непустой.
- Подпись.

Вложение — книга Excel (реестр + листы аналитики). Письмо формируется и **уходит
автоматически** (без подтверждения). Получатели — из `recipients.txt`.
`send_email.py --note` оставляем для ручных прогонов; в авто-режиме записка
встраивается напрямую в HTML.
