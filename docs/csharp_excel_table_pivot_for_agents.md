# C# Excel: умная таблица и сводная для агентов

Эта заметка нужна будущим агентам, которые будут править файл хронометража. Главный принцип: реестр должен быть настоящей умной таблицей Excel, а лист со сводной должен быть настоящей PivotTable, а не нарисованной таблицей.

## Что нельзя делать

- Не использовать LibreOffice/soffice: на сервере его не должно быть.
- Не заменять PivotTable обычной таблицей значений: пользователь проверяет, что это именно Excel-сводная.
- Не делать источник сводной диапазоном вроде `A1:U44249`, если можно сделать источник `Таблица1`.
- Не завязываться на жесткие номера колонок без проверки заголовков: состав реестра уже менялся.
- Не оставлять устаревшие поля в pivot cache после удаления колонок из реестра: Excel может открыть файл с восстановлением.

## Целевая структура книги

Обязательные листы:

- `Сводный_Реестр` - реестр как умная таблица `Таблица1`.
- `Сводная_пески` - настоящая PivotTable.
- `Проверка_объемов` - сверка объемов по подразделениям.
- `Комплектность_исходников` - контроль свежести исходников.
- `Файлы` - список использованных файлов.
- `Ожидаемая_сводная` - расчетная сверка для контроля.
- `Контроль_сводной` - вспомогательная C#-сводка значений.

## Как делать умную таблицу в C#

Используется EPPlus. Схема работы:

1. Открыть подготовленную Python книгу.
2. Прочитать лист `Сводный_Реестр` в `object[,]`.
3. Удалить служебные/ненужные колонки до загрузки в итоговый шаблон.
4. Открыть `pivot_template.xlsx`.
5. Полностью очистить старый лист `Сводный_Реестр`.
6. Загрузить массив данных через `LoadFromArrays`.
7. Создать ExcelTable:

```csharp
var table = ws.Tables.Add(ws.Cells[1, 1, rowCount, colCount], "Таблица1");
table.TableStyle = TableStyles.Medium7;
table.ShowFilter = true;
```

8. Отформатировать заголовок: синий фон, белый жирный текст, перенос строк.
9. Для дат поставить формат `[$-419]d\ mmm;@`, чтобы Excel показывал `18 май`, а не ISO-дату.
10. Ужать ширины колонок по словарю, а не AutoFit: AutoFit часто делает файл слишком широким.

Важно: после создания таблицы фактический диапазон должен быть вроде `A1:U44249`, а имя таблицы именно `Таблица1`.

## Как делать источник сводной

Лучший вариант для этого проекта: держать настоящую PivotTable в шаблоне Excel и C#-кодом менять ее источник/кэш.

После сохранения EPPlus файл открывается как ZIP, затем правятся XML-части:

- `xl/tables/table1.xml`
- `xl/worksheets/sheet*.xml`
- `xl/worksheets/_rels/sheet*.xml.rels`
- `xl/pivotCache/pivotCacheDefinition*.xml`
- `xl/pivotCache/pivotCacheRecords*.xml`
- `xl/pivotTables/pivotTable*.xml`
- `[Content_Types].xml`
- `xl/workbook.xml`

В `pivotCacheDefinition` источник должен быть:

```xml
<worksheetSource name="Таблица1"/>
```

Также ставить:

```xml
refreshOnLoad="1"
invalid="1"
```

Это заставляет Excel обновить кэш при открытии, но файл уже должен быть внутренне согласован до открытия.

## Как настроить поля сводной

Требуемая сводная для песков:

- Фильтр: `Дата выдачи наряд-задания`
- Фильтр: `Передел`
- Строки: `Дата. Факт`, `Время`
- Столбцы: `Подразделение`
- Значения: сумма `Обьем работ, м3`

Фильтр даты ставится на дату отчета. В автосценарии это обычно текущий день минус 1.

Фильтр переделов оставляет только:

- `Транспортировка песков`
- `Подача песков`

Если в реестре `Передел = Транспортировка песков`, а в `Примечание` есть слово `Склад`, Python должен переименовать строку в `Транспортировка песков на склад`. Этот передел не должен попадать в текущую песковую сводную, если пользователь не попросит иначе.

## Как не сломать фильтры PivotTable

Нельзя просто поменять текст в ячейках. У PivotTable есть собственные списки элементов в `sharedItems`.

Для даты:

1. Найти cacheField по заголовку `Дата выдачи наряд-задания`.
2. Убедиться, что в `sharedItems` есть элемент:

```xml
<d v="2026-07-03T00:00:00"/>
```

3. Запомнить индекс элемента.
4. В `pivotTable*.xml` прописать `pageField` с этим индексом.

Для передела:

1. Собрать уникальные значения из реестра.
2. Нормализовать дубли названий: пробелы, регистр, неразрывные пробелы.
3. Пересобрать `sharedItems` для поля `Передел`.
4. Выбранные индексы оставить видимыми, остальные скрыть через `h="1"`.
5. После изменения порядка элементов обязательно переназначить индексы в `pivotCacheRecords*.xml`.

Для времени:

1. Найти cacheField `Время`.
2. Отсортировать элементы по настоящему времени: `00:00`, `01:00`, ..., `08:00`, `09:00`, ..., `23:00`.
3. Если есть минуты, сортировать внутри часа: например `18:50`, затем `19:00`, `19:30`.
4. Переназначить индексы в `pivotCacheRecords*.xml`.
5. Обновить items у pivot field `Время`.

Старый порядок `09:00 ... 08:00` больше не использовать, если пользователь явно не попросит сменную сортировку.

## Если удаляются колонки реестра

Удаление колонок надо делать в двух местах:

1. Из данных реестра до создания `Таблица1`.
2. Из XML PivotTable/cache, если эти поля были в шаблоне.

Иначе Excel может открыть книгу с предупреждением о восстановлении.

Текущий пример: удалены колонки:

- `Ф.И.О. моториста п/п 1`
- `Ф.И.О. моториста п/п 2`

После удаления надо проверить:

- количество колонок на листе равно количеству `cacheFields`;
- удаленных заголовков нет в `Сводный_Реестр`;
- удаленных заголовков нет в `pivotCacheDefinition`;
- `pivotFields count` согласован с `cacheFields count`.

## Контроль объемов

Перед отправкой обязательно смотреть JSON метаданных рядом с финальной книгой:

- `volume_check` должен быть весь `OK`;
- `freshness_check` должен быть весь `OK`;
- обязательные подразделения: `Дражный`, `Обман`, `Сайлык`, `Талынья`, `Эрел`;
- `.xlsb` нужно читать, потому что Дражный присылает именно такой формат.

Если свежих данных нет, не отправлять молча старый файл. Надо остановиться и показать, по каким подразделениям нет свежего исходника.

## Частые причины ошибок Excel

- В workbook осталось несколько `table*.xml` с именем `Таблица1`.
- В `table1.xml` диапазон не совпадает с фактическим диапазоном листа.
- В worksheet relationships остались ссылки на удаленные table parts.
- `cacheFields count` не совпадает с количеством `cacheField`.
- `pivotFields count` не совпадает с количеством `pivotField`.
- Из `sharedItems` поменяли порядок, но не переназначили индексы в `pivotCacheRecords`.
- Фильтр PivotTable ссылается на несуществующий item index.
- Даты записаны строками в одном месте и date-items в другом.
